## 清单与处理结果

| 维度 | 本轮发现与处置 |
|---|---|
| 清晰度 / 复杂度 | 将配置读取和持久化从应用宿主抽出为 Preferences.cs；没有增加接口层、依赖注入框架或通用配置抽象。 |
| 无用代码 | 调用点检索确认旧菜单字体注册/释放路径已无调用者，移除 GDI/GDI+ 注册与非托管内存管理代码。WPF 内嵌字体保留，原生菜单仍使用系统字体。 |
| 配置可靠性 | 以前直接覆盖目标文件且吞掉写入错误；现在先写同目录唯一临时文件，再用系统 File.Replace/File.Move 完成替换。失败保留旧文件、清理临时文件，向宿主返回失败并通过托盘通知本次选择未持久化。不能据此承诺断电后的存储设备持久性。 |
| 重复操作 / 生命周期 | 线程自己在 finally 释放等待事件，Dispose 可重复调用；重试改用可被新请求/退出唤醒的等待，仍不在 UI 线程 Join，也不强制中断延迟剪贴板读取。构造失败释放事件，拒绝空回调和空请求。 |
| 输入与状态 | 暂停及切换样式时重置复制按键状态，避免遗漏松键导致下一次快捷键被当成长按；保留原复制来源、序号及超时判断。 |
| 错误可见性 | 配置失败有用户提示；启动、Dispatcher、剪贴板读取和任务栏探测异常向 .NET Trace 输出类型与 HRESULT，不记录异常消息、窗口标题、文件名或剪贴板内容。TRACE 构建符号已启用；默认不创建日志文件，因此这不是持久化日志系统。 |
| 测试保护 | 新增独立 QualityChecks，不读取真实剪贴板内容、不写真实设置或自启动；覆盖配置初次/覆盖/锁定失败/未知字段、按键去重与重置、预览清理、复制确认/重复/保留/超时、剪贴板句柄关闭、自启动幂等与路径引号、工作线程退出及等待事件释放。 |
| 性能 / 资源 | 重试间隔数组从每个请求创建改为每个线程复用；无阴影背景不再分配两块阴影数组。96 DPI 省 221,952 字节、168 DPI 省 680,064 字节临时分配/次背景重建；背景缓存命中时本来就不会分配，不能将此换算为同等常驻工作集下降。 |
| 依赖与复用 | 复用 .NET Framework 文件替换、等待事件和现有状态机/渲染缓存；不新增 NuGet 或外部组件，不替换四倍文字渲染及 Windows Composition 实现。应用没有业务网络请求，HTTP 重试不适用。 |

## 保留问题与后续边界

- 任务栏 UIA 快照仍可能阻塞或不完整；左侧试验锚点仍可能覆盖控件。此次不更改已讨论的避让产品策略，也未宣称多屏、美化工具和全屏兼容已解决。
- 外部应用的延迟剪贴板读取仍不能安全强制中断；退出只停止后续工作，后台线程返回后释放等待事件。
- UI 线程与静态 ToastProfile/Theme 仍存在耦合；目前通过关闭旧窗再切换确保串行生命周期。为减少审查风险，本轮没有同时重构整个渲染架构。
- 没有逐平台验证所有 COM 接口、未知格式和字体回退；现有自动化不能证明程序不存在所有故障。
- 不新增长期磁盘日志，不记录个人数据；Trace 的实际收集由调试监听器决定。
- 不承诺固定内存/帧率改善，不使用强制 GC、工作集修剪或减少文字采样。
