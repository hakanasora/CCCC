# 普通卡片弹跳时的材质边缘闪烁

2026-11-09，本地修复基于 2.4.8-preview.1。任务栏避让、设置提示串用和发行签名不在本次修改范围内。

## 复现与机制

用户在 1080P、100% 缩放的外接屏上观察到普通卡片只在弹跳时闪边。开启高级材质时深浅主题均可出现，关闭材质后未见同样问题。任意应用窗口仅与提示区域部分重叠就能消除明显闪烁。低刷新率更明显。用户另测 2.4.6 也有问题。

本机 AMD Radeon 880M、1920×1080、100% 缩放、120 Hz 上复现了双边界，并复现部分下方窗口可以抑制明显露边的现象。逐帧分析了用户录像，未将手机拍摄的曝光重影作为独立根因证据。

原路径由 WPF 绘制带颜色、描边和阴影的背景位图，另一个原生窗口绘制 HostBackdrop 毛玻璃。两者在同一回调中设置相同缩放值，但经过独立呈现管线。把原生画刷换成纯洋红色仍出现露边，说明模糊计算不是该错位的必要条件。静止时两层可以重合，运动中会分离。

这足以确认本次需要消除的错误状态是底板边界和材质边界独立运动。它没有证明不同背景下 DWM 内部如何调度，也没有证明所有用户视频中的每个亮点都来自同一机制。

## 修改

复用原来的 BackgroundFrame 和 Pbgra32 像素，把背景上传到 CompositionDrawingSurface。原生 ContainerVisual 同时包含原 HostBackdrop 毛玻璃和背景位图，统一缩放与淡入淡出。只有毛玻璃受轮廓裁剪，背景图的阴影边距保留。

文字、图标和计数仍由现有 WPF 内容绘制。四倍文字采样、字体、颜色、模糊参数、布局与弹跳曲线不变。上传只在背景帧变化时发生，同一帧引用不重复上传，不进行逐帧整卡截图。

新增的 CompositionBitmap 集中拥有系统 D3D11、D2D 与 Composition 表面资源，没有增加第三方运行依赖。使用 BGRA premultiplied alpha、实际像素尺寸及 BeginDraw 返回的偏移。材质或上传失败恢复 WPF 不透明背景，关闭材质会释放新增资源。

接口与 ABI 参照本机 Windows SDK 10.0.26100.0 及微软的 [Composition 原生互操作示例](https://github.com/microsoft/Windows.UI.Composition-Win32-Samples/blob/master/cpp/ScreenCaptureforHWND/ScreenCaptureforHWND/composition.interop.h)，沿用项目现有 COM 委托写法。没有引入 Win2D 或 Windows App SDK。单纯增加 DwmFlush 没有跨两管线原子提交保证，因此没有采用。更换普通 Backdrop 画刷会改变模糊外观，也没有解决独立运动归属，因此没有作为最终修复。

## 实际检查

- 使用同一个最终诊断程序编译基线源码与修复源码。旧源码的 72 个有效弹跳捕获帧中，外露洋红像素峰值 1022，超过容差 120，进程返回 1。修复后的深色 96 帧、浅色 64 帧均为 0，分析器返回 0。所有有效帧都确认材质及标记仍有效，并检查卡片内部确实含标记。
- 真实材质的深浅主题、纯桌面、部分蓝色下方窗口和动态棋盘均已运行并检查截图序列。关闭材质也已运行。未观察到原先那种数像素宽的材质露边。
- 生命周期检查通过材质关闭、模拟创建失败、上传无效像素格式后的不透明回退，以及重新开启。没有模拟实际显卡设备移除。
- 44 项质量断言、128 项任务栏离屏断言、28 项普通卡片动画检查通过。任务栏离屏检查包含 154、168 DPI 的字形与计数布局。
- 原生上传 probe 检查了 96、120、144、192 DPI 对应像素尺寸、重复使用同帧及重复释放。该检查不是在这些缩放比例的真实屏幕上拍摄。
- 独立审查核对了 COM GUID、方法顺序、D2D 槽位、像素格式、偏移与主要失败路径。测试中的错误通过风险已经修正。

可重复执行的入口见 [材质检查说明](../../tests/material/README.md)。录屏、截图、试验画刷和中间输出保留在本地 artifacts/flicker，不随源码提交。

## 适用范围

实机结果来自上述 880M 环境。没有在朋友的 RTX 4070 Laptop GPU、50 或 60 Hz 上完成修复后复验，没有进行硬件兼容矩阵或内存基准。新表面和图形设备会占用资源，不能承诺内存下降。底板与材质现在共用运动归属，文字仍由 WPF 呈现，不宣称整个窗口的所有内容已变成单一呈现管线。

版本元数据仍为 2.4.8-preview.1，本地试用文件名另带 material-fix，尚未发布为新的 GitHub Release。使用前退出旧版，在普通样式下复验原触发场景。
